# DeepSeek Harness 源码阅读指南

> 面向要在本地 WebStorm 源码调试并阅读 DeepSeek Harness 的开发者。
> 本文件为个人学习笔记，未纳入 doc-sync 门禁；与 `docs/architecture.md` 冲突时以后者为准。
> TS 零基础先看 [4-TypeScript基础语法和基础类型](4-TypeScript基础语法和基础类型.md)；
> 按本项目定制的进阶清单见 [1-TypeScript前置知识清单](1-TypeScript前置知识清单.md)。

## 第零步：本地 WebStorm 源码调试环境搭建

### 克隆仓库与分支策略

```sh
cd WebstormProjects
git clone https://github.com/shandian534/deepseek-harness.git
cd deepseek-harness
git remote add upstream https://github.com/deepseek-ai/deepseek-harness.git
```

用 WebStorm 打开后，**新建一个分支专用于源码注释**。后续官方仓库有更新时，先同步到自己 fork（`git fetch upstream && git merge upstream/master` 并推送 origin），再合到注释分支——注释工作不阻塞，官方更新也能持续跟进。

### 安装与构建

```sh
pnpm install
pnpm run build   # 源码调试需要先构建：web-app 要 serve 前端 dist/，typert loader 走包 exports 的 lib/
```

### 配置 WebStorm 调试运行配置

Run → Edit Configurations → + → Node.js：

| 字段 | 值 |
|---|---|
| Node interpreter | Project（Node ≥22.19 或 ≥24） |
| Node parameters | `--import tsx/esm` |
| JavaScript file | `<仓库根>/apps/cli/src/bin.ts` |
| Parameters | `--profile web` |
| Working directory | 仓库根目录 |

（原笔记此处有一张运行配置截图，见 Evernote 原文）

### 配置 API Key

在仓库根目录创建 `.env` 文件（已被 gitignore，不会提交）：

```
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

> ⚠️ 不要把真实 key 写进任何会提交或分享的文档；`loadLayeredEnv` 启动时会自动按 调用目录 `.env` → dsh home `.env` 分层加载。

### 验证启动

点击 WebStorm 的 Debug 按钮，控制台出现以下输出表示配置成功：

```
/usr/local/bin/node --import tsx/esm /Users/shandian/WebstormProjects/deepseek-harness/apps/cli/src/bin.ts --profile web
Debugger listening on ws://127.0.0.1:56691/435973a2-8882-4543-a99f-f03ff7f9f272
For help, see: https://nodejs.org/en/docs/inspector
Debugger attached.
dsh web: http://127.0.0.1:3080
```

浏览器访问 `http://127.0.0.1:3080`，在 `.ts` 文件上打断点即可命中（tsx 生成内联 sourcemap）。

## 第一步：先建立 Cordis 心智模型

不读框架直接读源码会全程迷路——这个项目一切皆插件。

1. **[cordis-primer.zh.md](../cordis-primer.zh.md)** — Context/Fiber/事件/瀑布监听语义，约半小时
2. **[architecture.zh.md](../architecture.zh.md)** — 只有 129 行，讲 profile/bundle 分层组合、核心包的 `ctx` 键、事件体系分类
3. 遇到术语查 **[glossary.zh.md](../glossary.zh.md)**（capability seam、Service Definition/Provider/Consumer 这些自造概念都有定义）

## 第二步：核心脊柱五包（按依赖顺序读）

```
core/session        → ctx.sessions     append-only 事件日志（一切的根基）
core/system-prompt  → ctx.systemPrompt 提示词与工具 schema 组装
core/tools          → ctx.tools        工具注册与受护执行管道
core/agent          → ctx.agents       Agent 接口与生命周期
core/agent-loop     → ctx.agentLoop    默认驱动循环
```

每包配套读 [subsystems](../subsystems/) 下的对应文档（[session.zh.md](../subsystems/session.zh.md)、[tools.zh.md](../subsystems/tools.zh.md)、[core.zh.md](../subsystems/core.zh.md)…），它们比 README 更聚焦数据流。

## 第三步：用调试器做一次端到端追踪

理解 agent harness 最快的方式，比静态读码高效得多。

1. Debug 启动 web profile，在 `packages/core/agent-loop/src` 的主循环入口打断点
2. 浏览器 UI 发一条消息，沿线追：`session/event` 追加 → system-prompt 组装 → LLM 请求（`llm/llm` 的流式适配层）→ 工具执行管道（[tool-execution-pipeline.zh.md](../tool-execution-pipeline.zh.md)）→ 事件回流
   - 实战调用栈示例见 **[5-调用栈分析-插件加载与工具执行](5-调用栈分析-插件加载与工具执行.md)**（插件重载循环、工具派发完整链路、关键断点位置）
3. 配合 `dsh --profile web --dump-config` 看你机器实际启动的插件树，把断点跟树的行对应起来

## 第四步：按需分叉 + 查「为什么」

- **改什么学什么**：[cookbook](../cookbook/) 有 [adding-a-tool.zh.md](../cookbook/adding-a-tool.zh.md) / [adding-a-package.zh.md](../cookbook/adding-a-package.zh.md) / [adding-an-llm-adapter.zh.md](../cookbook/adding-an-llm-adapter.zh.md)，按成品路径走一遍结构最清楚
- **决策依据**：[.agents/notes/implemented](../../.agents/notes/implemented/) 分 architecture/feature/process/simplification/testing 六类，是高质量 ADR；改某块代码前先看有没有对应 note
- **已知坑**：[postmortem](../postmortem/) 的复盘（默认导出丢 inject、landlock 误报等），都是这个代码库特有的坑
- **索引类**：[module-graph.zh.md](../module-graph.zh.md)、[tool-catalog.zh.md](../tool-catalog.zh.md)、[config-catalog.zh.md](../config-catalog.zh.md) 都是生成的，当字典查，不当书读

## 两条务实建议

1. **让 agent 替你扫**：architecture.md 开头自己就写着 "We recommend using an agent to explore the codebase"。范围明确的问题（「工具超时在哪强制执行」）派 Explore agent 去搜，自己保留核心链路的精读
2. **vendor/ 先绕开**：vendored Cordis 当黑盒用 primer 的语义文档就够了，除非要改框架本身（改它有严格的 sync 流程，见 `vendor/README.md`）

## 附：调试环境备忘

- 启动向量：`node --import tsx/esm apps/cli/src/bin.ts`（root `package.json` 的 `dsh` 脚本；tsx ESM hook 负责 TS 转换与 tsconfig paths）
- web profile 需要先 `pnpm run build`（web-app 要 serve 前端 `dist/`，typert loader 按包 `exports` 走 `lib/`）
- 改宿主面 `src/*.ts` 后需重跑 `pnpm run build:lib:host` 再重启调试；改前端/client 插件跑 `pnpm run dev:web -- --poll` 热重建
- `.env`（仓库根，gitignored）放 `DEEPSEEK_API_KEY`；tui profile 需要 TTY，IDE 管道下会拒绝启动，交互调试用 web
