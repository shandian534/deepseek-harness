# 调用栈分析：插件加载与工具执行

> 本文件为学习笔记，未纳入 doc-sync 门禁；内容基于 WebStorm 调试器截图的真实调用栈。
> 配合 [0-源码阅读指南](0-源码阅读指南.md) 的第三步（端到端追踪）使用。

## 图一：插件初始化/重载循环（`vendor/cordis/src/fiber.ts`）

**场景**：一个插件的 `apply()` 方法被调用，触发 Fiber 的内部状态重载。

```
apply(), my-plugin.ts:15           ← 插件入口
execute(), fiber.ts:253            ← 执行 effect
anonymous(), fiber.ts:366          ← effect 包装器
composeError(), utils.ts:272       ← 错误包装
_execute(), fiber.ts:358           ← 执行逻辑
_reload(), fiber.ts:656            ← 重载插件（循环点）
```

**关键观察**：

1. **Fiber 的 `_reload()` 是核心重载入口**（`fiber.ts:656`）
   - 调用链路：`_reload()` → `_updateState()` → `_setEpoch()` → `_refresh()`
   - `_refresh()` 触发状态变化通知 `notify()`（`reflect.ts:326`）
   - 整个链路重复 3 次：**每个依赖重载的插件都会触发一轮**

2. **最终落地到插件初始化**：
   ```
   Fiber(), fiber.ts:318              ← 创建 Fiber 实例
   plugin(), registry.ts:330          ← 注册插件
   _start(), entry.ts:296            ← 启动入口
   Async call from await             ← 异步等待
   _init(), entry.ts:285             ← 初始化
   ```

3. **异步链路**：多处 `Async call from await` —— Cordis 插件体系是异步优先，每个重载/初始化都可能是 Promise

**知识点**：
- **Fiber** 是 Cordis 的执行上下文/生命周期管理器，每个插件在独立 Fiber 里运行
- **Epoch** 是 Fiber 的时代标记，每次状态更新递增，用于订阅/通知
- **Effect** 是「注册-拆卸」模式的抽象，`execute()` 返回的 disposer 会在 unload 时自动调用

## 图二：工具调用的完整执行链路

**场景**：从 `execute()` 发起工具调用，最终走到 agent 的 `step()` 循环。

```
execute(), my-plugin.ts:43                      ← 你的代码发起工具调用
execute(), schema.ts:588                        ← 工具 schema 校验
dispatchToolBody(), index.ts:1549               ← 工具分发
anonymous(), index.ts:1575                      ← 转换入口
next(), events.ts:239                           ← 事件派发
anonymous(), index.ts:74                        ← 事件处理
Async call from await                           ← 等待异步派发
apply(), reflect.ts:411                         ← 应用事件
next(), events.ts:239                           ← 继续派发
anonymous(), index.ts:59                        ← 处理事件
apply(), reflect.ts:411                         ← 再应用
next(), events.ts:239                           ← 再派发
waterfall(), events.ts:242                      ← 瀑布流（依次监听器）
dispatchScheduledExecution(), index.ts:1573     ← 调度执行
dispatch(), index.ts:798                        ← 派发到具体处理器
startCall(), tool-calls.ts:173                   ← 启动工具调用
Async call from await                           ← 等待工具池
fillPool(), tool-calls.ts:205                   ← 填充工具池
runGroup(), tool-calls.ts:219                    ← 分组运行
executeToolCalls(), tool-calls.ts:90             ← 执行工具
step(), agent.ts:395                             ← agent 步进循环
```

**文件定位**（关键节点）：

| 调用节点 | 文件路径 | 职责 |
|---|---|---|
| `schema.ts:588` | `packages/core/tools/src/schema.ts` | 工具参数 schema 校验 |
| `dispatchToolBody()` | `packages/core/tools/src/index.ts:1549` | 工具分发入口 |
| `next()` / `waterfall()` | `vendor/cordis/src/events.ts` | 事件派发/瀑布流 |
| `apply()` | `vendor/cordis/src/reflect.ts:411` | 应用事件到监听器 |
| `dispatchScheduledExecution()` | `packages/core/tools/src/index.ts:1573` | 调度工具执行 |
| `startCall()` | `packages/core/agent-loop/src/tool-calls.ts:173` | 工具调用生命周期 |
| `fillPool()` / `runGroup()` | `packages/core/agent-loop/src/tool-calls.ts` | 工具池管理 |
| `executeToolCalls()` | `packages/core/agent-loop/src/tool-calls.ts:90` | 实际执行 |
| `step()` | `packages/core/agent-loop/src/agent.ts:395` | agent 单步循环 |

**关键观察**：

1. **三层派发**：
   - 你的 `execute()` → `schema.ts:588` 校验
   - `dispatchToolBody()` → 进入工具系统
   - `events.ts` 三重 `next()` + `waterfall()` —— **事件派发是核心管道**

2. **瀑布流（waterfall）是事件传播模式**：
   - 每个监听器可以修改传给下一个的数据
   - 不同于 `parallel`（并发），`waterfall` 是串行链式

3. **工具池与分组**：
   - `fillPool()` / `runGroup()` —— 工具可能有依赖关系，需要分组按顺序执行
   - `startCall()` 是每个工具调用的生命周期封装

4. **最终落到 agent 的 `step()`**：
   - 工具执行是 `step()` 循环的一部分
   - `step()` 会等待工具结果，继续下一轮模型请求

**知识点**：
- **事件派发是 Cordis 的核心扩展机制**：`tools/*` 事件负责工具策略/超时/权限控制
- **瀑布流 vs 并发**：工具执行用瀑布流（可改参数），监听器可以用并发（性能优先）
- **工具池**：相同配置的工具可以复用连接/进程，`fillPool()` 是预热阶段
- **agent-loop 的 `step()`** 是驱动循环的「回合」，包含「请求模型 → 解析工具调用 → 执行工具 → 收集结果」一个完整闭环

   - `vendor/cordis/src/events.ts:242`（`waterfall`）

   - `packages/core/agent-loop/src/agent.ts:395`（`step`）

   - `vendor/cordis/src/fiber.ts:656`（`_reload`）
